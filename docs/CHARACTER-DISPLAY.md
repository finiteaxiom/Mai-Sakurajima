# 头像、桌宠与衣橱展示规范

本规范约束展示，不改变已接受的原版与三套 Q 版服装，不以放大、锐化或逐帧独立缩放替代素材制作。Live2D 制作仍冻结。

## 四种展示用途

| 用途 | 内容尺寸 | 裁切与留白 | 缩放规则 |
| --- | --- | --- | --- |
| Chat 侧栏头像 | 38×38 CSS px；消息头像 32×32，设置用户头像 36×36 | 圆形，`object-fit: cover`；头像允许居中裁切 | 普通图片插值，不复用全身精灵图 |
| 桌宠 | 内部 canvas 192×208；既有 CSS 240×260，原窗口 310×390 | 原位显示，保留透明边缘与交互区域 | 本轮不改变位置、窗口大小与原有 CSS 比例 |
| 衣橱缩略图 | 内部 canvas 192×208；CSS 96×104 | 完整人物，保留原画布留白 | 固定二分之一尺寸，像素边缘；不按人物边界单独裁切 |
| 衣橱动作预览 | 内部 canvas / CSS 均为 192×208 | 人物与透明边缘完整；加载失败保留占位几何 | 宽窄窗口统一尺寸，不随可用空间拉伸 |

第四阶段前衣橱大预览为 240×260 CSS px、窄窗口为 192×208。本轮统一到 192×208，减少非整数 CSS 放大。以上均是 CSS / canvas 单位，不等于显示器物理像素，也不等于原始 PNG 精灵图分辨率。高 DPI 下仍由 Chromium 合成；不声称可消除所有像素阶梯或提升素材本身精度。

`pet-sprites.js` 的 `imageSmoothingEnabled=false`、每套共用 `174 / standingHeight` 比例、横向锚点与脚底线 198 保留。原版仍按等距格裁切，新衣服仍使用 metadata source rectangle；行走仍读取独立补图。不得逐帧按包围盒缩放，也不得把这些固定画布常量直接套在不同内部尺寸的 canvas 上。

## 状态与回退

- 当前穿着来自 Main 的衣橱快照/事件；正在预览是 Renderer 的临时选择。点击服装不保存，明确点击应用才请求保存。
- 保存中禁用选择与重复应用；保存成功后显示结果，失败保留旧穿着与预览。拖动期间切换仍由桌宠在释放后应用。
- 读取失败显示“尚未读取”，禁用应用，允许预览和重试，不猜测已穿原版。
- 素材加载失败保留空白占位、显示素材不可用，禁用动作及应用；重试成功恢复缩略图和预览。暂停时选择新服装或动作会绘制新内容的首帧，不显示上一套的旧画面。
- 用户没有选择头像时继续使用既有默认资源。默认资源或用户本地图片缺失/损坏时，`avatar-fallback.js` 使用本仓库绘制的中性人物 SVG；只覆盖头像元素，不替换背景、精灵或其他图片。失败不写设置、不删除用户副本，也不加载外网素材。用户下次选择有效图片仍可正常显示。

## 验收方法

静态检查按自然内容尺寸观察眼睛、发夹、腿部与留白，记录实际 `screen.scaleFactor` 和 Renderer `devicePixelRatio`。截图以高 DPI 导出后的像素尺寸不能当作 CSS 尺寸。

动态检查区分：播放器时间推进、实际脚部姿态、整体观感。四套均检查待机、挥手、左右行走、摸头回应、困倦及两项专属动作；新装另保留被提起和落地。帧哈希不同仅证明发生变化；三套新装另检查脚部跨步/收腿轮廓，并人工阅读接触表。素材固有的线条、头身比例与姿态差异仍可能可见，不能由自动化推断为用户满意。

`node test/pet-wardrobe-smoke.js` 使用真实窗口管理、preload、衣橱 IPC、素材和临时磁盘设置；可用 `MAI_WARDROBE_OUTPUT` 指定截图目录。覆盖保存/重载、错误回退、暂停切换、明暗与窄窗、头像解码失败，并输出四套动作接触表。真实服务、系统多 DPI 切换和安装升级另行验收。具体记录见 [阶段 D 报告](../artifacts/ui-maturity/stage-d/REPORT.md)。
