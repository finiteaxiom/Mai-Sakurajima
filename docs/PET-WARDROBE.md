# 桌宠衣橱与动作

## 使用入口

- 桌宠右键或托盘菜单 → 衣橱与动作。
- Chat 设置 → 桌宠衣橱 → 衣橱与动作。
- 点击服装卡片只预览，点击「换上这套」才保存；关闭衣橱不关闭 Chat，也不触发语音停止。
- 原版装扮始终保留。新装扮是校服、居家针织衫、冬季大衣。
- 衣橱可以选择动作、重新播放、暂停；桌宠右键的「互动」也包含当前服装的两个专属动作。

## 动作与素材

`renderer/media/wardrobe/{school,home,winter}.png` 为内置 imagegen 生成的透明动作图。
每套有 8 组、每组 4 个关键姿态，共 32 帧；它们是有限帧精灵动画，不是 Live2D，也不是 60 张独立图像/秒。

原整图第 1 行的步态变化不足，已停用；实际行走读取独立的 `school-walk.png`、`home-walk.png`、`winter-walk.png` 及其 JSON 坐标。每张补图是 2×2 四帧：近腿前跨、远腿屈膝经过、远腿前跨、近腿屈膝经过。播放器按此顺序循环，左行镜像同一步态；其余动作保持原整图。加载或应用装扮时同时校验补图，缺失时不应用不完整的服装。

| 行 | 动作 | 播放方式 |
|---|---|---|
| 0 | 待机 / 眨眼 | 延长睁眼停留，再播放闭眼和恢复 |
| 1 | 行走 | 使用独立的 `*-walk.png` 四帧步态替换该行；向左通过镜像呈现 |
| 2 | 挥手 | 抬手后循环轻摆，退出时放下 |
| 3 | 摸头回应 | 轻闭眼、低头、恢复 |
| 4 | 被提起 / 落地 | 拖动时使用前两帧，释放后使用后两帧 |
| 5 | 困倦 | 进入后循环闭眼姿态，退出恢复 |
| 6 | 专属动作一 | 校服读书、居家喝茶、冬装整理围巾 |
| 7 | 专属动作二 | 校服整理领结、居家伸懒腰、冬装暖手 |

新服装没有单独绘制旧版所有情绪、工作、零食及 16 方向视线帧。遇到未支持的旧动作，保持当前衣服并使用待机呈现；校服的 `study` 使用读书帧。原版保留既有全部动作和视线逻辑。新服装的闲置活动从专属动作、挥手和困倦中选择。移动与过渡使用少量关键帧，动作精细度仍以用户动态验收为准。

`scripts/inspect-pet-sheet.py` 只分析 alpha 像素并生成同名 JSON 坐标，不修改 PNG。开发时需要 Pillow / numpy / scipy，产品运行不需要 Python。因为生成图并非严格等距网格，不能直接按等宽格子截取。

行走补图的坐标命令为 `python scripts/inspect-pet-sheet.py renderer/media/wardrobe/school-walk.png 2 2`，其余两套替换文件名。

`renderer/pet-sprites.js` 使用每帧 source rectangle、头部横向锚点、统一脚底线和每套共用缩放比例，避免逐帧独立缩放导致人物忽大忽小。它只稳定几何位置，不能消除生成图本身的线条和姿态差异。预览与桌宠使用同一播放器。系统减少动画设置优先；衣橱也读取现有外观动效设置。待机动作没有调用模型或外部服务。

## 状态与安全边界

- `renderer/pet-catalog.js` 是静态服装与动作目录；不接受用户提供的路径、脚本或网络资源。
- `pet-wardrobe.js` 注册 `wardrobe:open/get/set`。只接受既有 pet、Chat、wardrobe 窗口的顶层 frame；`set` 只接受目录内的服装 ID。
- Main 检查图片与坐标文件后，调用原有 `saveSettings()` 原子保存，再广播 `wardrobe:changed`。
- 保存位置：`%APPDATA%\Mai Sakurajima\mai-pet-deepseek-settings.json` 的 `petWardrobe.outfitId`。
- 这个字段独立于旧版已退役的 `outfit` / `outfitCatalogVersion`，不复活旧迁移字段。
- Renderer 仅拥有预览选择、已加载素材与拖动结束前的待应用选择，不直接写文件。
- 换装先加载再替换；加载失败保留当前图片，保存失败回滚设置；快速连续选择以最后一次为准。拖动结束后才应用新服装。
- 衣橱是 `window-manager.js` 管理的独立窗口，不改变桌宠位置、大小、Chat 历史、记忆或语音生命周期。
- `renderer/**/*` 已包含全部新 PNG / JSON / JS / CSS，新增主进程模块已加入打包白名单。

## 绘图提示词与来源

使用内置 imagegen，原始衣服设计由用户在本线程审阅通过。三套动作图使用各自已通过的造型图为角色参考；校服动作图也作为后两套的布局参考。

共同生成提示：透明像素风；同一人物脸型、长发、发夹和服装；4 列 × 8 行、32 个完整人物；每格留空白；人物比例稳定；无文字、网格、场景、兔耳。逐行绘制：眨眼、向右步态、挥手、摸头回应、提起与落地、困倦、专属动作一、专属动作二。

行走补图追加提示（内置 imagegen）：以各套已通过的造型为参考，绘制 2×2 四个完整侧身朝右的人物；第 1、3 帧为相反腿在前的宽跨步，第 2、4 帧为不同腿屈膝向前、支撑腿竖直的窄轮廓；手臂反向摆动，头、躯干和比例稳定，透明背景、无字、无场景，不能用四个相似跨步姿态替代行走循环。

- 校服：米色开衫、酒红领结、深蓝百褶裙、深色连裤袜、棕色鞋；第 6 行闭书→打开→阅读→翻页，第 7 行抬手整理领结。
- 居家：淡紫针织衫、象牙白长裤、深色拖鞋；第 6 行低位捧杯→举杯→小口喝→放低，第 7 行放松→举臂→伸展→放下。
- 冬装：驼色及膝大衣、酒红围巾、深色连裤袜、棕色短靴；第 6 行抬手整理围巾，第 7 行合拢双手→靠近嘴边暖手→放下。对初稿追加修正：所有帧把短外套改为与审阅稿一致的长大衣，保留 4×8 布局与动作。

## 验证

- `npm.cmd test`：仓库单元 / 契约测试，及迁移、恢复保护、Chat 流程 smoke。
- `node test/pet-wardrobe-smoke.js`：真实 Electron 窗口管理、preload、衣橱 IPC、实际 PNG / JSON 与磁盘设置夹具；独立临时 userData，不读取正式用户数据，不调用模型。
- 衣橱 smoke 覆盖原生菜单入口、三套预览与应用、预览不写入、窗口位置不变、动作帧变化、拖拽期间延后切换、写入失败回滚、磁盘重载恢复、还原原版及图片请求失败。
- 行走回归额外按真实播放器输出左右四帧，检查脚部区域的跨步/收腿宽度交替，而不是仅比较全图像素是否变化；并输出 `*-walk.png` 接触表供视觉检查。轮廓测试是必要检查，不能代替完整的动画观感验收。
- 截图和按实际播放器输出的逐帧检查图保存到 `logs/wardrobe-smoke/`，不属于发布资源。
- 语音真实设备通话、安装包安装 / 升级及长期运行不由这些 smoke 验证。
