## 3. 已确认问题

### A-01 / P1：保存完成覆盖保存期间的新草稿

- 页面：设置 → 陪伴偏好 → 自定义性格补充。
- 复现：填写“提交时的版本”；给合成保存调用增加 1000ms 延迟并点击保存；等待期间将字段改为“保存过程中继续输入的新版本”；等保存返回。
- 期望：用户不应丢失保存开始后的输入。若采用锁定策略，保存期间应不能再编辑普通配置字段；若允许继续编辑，应保留新版草稿与未保存标记。
- 实际：保存按钮被禁用，但字段仍可编辑；返回后字段回到“提交时的版本”，dirty=false，提示“设置已保存”。保存夹具中的值也为旧版。
- 原因：`renderer/chat.js` 的 `saveSettings()` 在异步返回后无条件调用 `populateSettings()`，后者重填字段并清除 dirty；`settings-view.js` 没有提交中的字段锁或版本保护。
- 证据：[结构化观察](evidence/audit.json)的 `saving` / `saveRace`；[保存中](evidence/08-saving.png)、[覆盖后](evidence/09-save-race.png)。该竞态在两次审计运行均出现。
- 影响：丢失当前窗口中新输入的未保存设置。不能据此推断已保存文件损坏。
- 下一阶段建议：以最小统一提交锁保护普通设置字段及所有“保存并…”操作。仍允许分类切换、关闭、查看诊断；保持独立头像/壁纸/衣橱操作的现有语义。如选择保留并合并新草稿，应单独实现版本保护。
- 拟修改：`renderer/chat.js`、`settings-view.js`、必要的 `product-layout.css` 及保存回归夹具。
- 验收：慢成功、慢失败、保存中切分类/关闭重开、连续触发不同保存入口；不得丢输入、并行覆盖或提前清除 dirty。继续通过真实 Main 保存失败回滚测试。

### A-02 / P2：错误信息只剥离 IPC 前缀，缺少用户层描述

- 复现：注入请求异常 `fixture: network unavailable` 或保存异常 `fixture: settings save failed`。
- 实际：提示直接展示异常消息；请求错误另有“编辑后重试”，保存错误没有下一步说明。
- 证据：`evidence/06-request-failed.png`、`07-save-failed.png`，以及 `chat.js` 的 `errorText()`。
- 影响：技术异常可能无法帮助用户理解该改配置还是稍后重试。本次不是线上错误样本采集，也未证实秘密泄漏。
- 建议：沿既有可靠错误码区分配置、连接和通用失败；未知错误提供中性说明；诊断仍使用既有脱敏入口，不将原始异常串任意转存日志。
- 拟修改：`renderer/chat.js` 的呈现映射及相关状态组件；必要接口缺口先列出，不从字符串猜测持久化结果。
- 验收：模拟错误和未知错误均有明确下一步，英文堆栈不直接成为主文案；不扩大日志敏感内容。

### A-03 / P2：取消成功后没有明确终态提示

- 复现：合成请求保持等待 → 点击停止 → 合成 Runtime 返回 cancelled=true。
- 实际：按钮恢复“发送”，临时用户消息和等待气泡移除；输入框与 notice 都为空。
- 证据：`evidence/04-cancelling.png`、`05-cancelled.png`，`audit.json.cancelled`，既有 Coordinator 清理逻辑。
- 影响：用户缺乏取消完成的确认，可能需要重新输入；这属于反馈缺口，不是已确认的取消传播故障。
- 建议：“本次回复已停止”；仅在没有新草稿时考虑恢复原输入。呈现层不得声称已保存/删除，仍按 Main 返回结果处理消息。
- 拟修改：`renderer/chat.js` 的取消反馈；继续复用 `chat-turn-coordinator.js` 的取消所有权。
- 验收：取消成功、取消拒绝、取消失败、晚到回复、切换会话均有相符反馈；重复点击不生成第二次请求。

### A-04 / P2：桌面折叠侧栏的组名换行，分组信息层级不稳定

- 复现：1180×820 内容尺寸 → 折叠侧栏 → 展开“一起生活”。
- 实际：72px 侧栏中“一起生活”和“记忆与资料”发生生硬换行；日程等仅剩图标，共同计划区隐藏，需要展开完整侧栏后访问。
- 证据：[折叠导航](evidence/10-collapsed-navigation.png)。这是可读性/发现成本问题，不是功能被删除。
- 建议：为折叠模式设计简洁的组入口与完整名称提示，或选择分组后展开侧栏；普通宽侧栏及手机式窄窗口逻辑保持各自清楚。
- 拟修改：`product-layout.css`、`chat.html` 和必要导航绑定。
- 验收：鼠标与键盘都能找到日程、记忆和共同计划；展开/折叠不丢原状态，无横向溢出。

### A-05 / P2：首次桌宠欢迎词没有引导核心聊天与模型连接

- 复现：以 firstLaunch=true 的内置 fallback 加载生产桌宠 Renderer。
- 实际：欢迎词主要介绍番茄钟与不可见模式；底部提示虽有“双击聊天”，欢迎词未解释聊天前的连接步骤。
- 证据：`evidence/00-first-run-pet.png`、`first-run.json`，`renderer/app.js` 的 firstLaunch 分支；聊天页本身已经有连接引导。
- 建议：欢迎词优先介绍“双击开始聊天，首次使用先连接模型”；不增加强制弹窗或新的注册流程。
- 拟修改：`renderer/app.js` 的引导文案及相关首次启动呈现。
- 验收：独立资料首次启动能够从桌宠进入聊天并看到连接入口；后续启动不反复弹出首次提示。真正安装版流程在阶段 E 验收。
